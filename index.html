V3 — current (what the PR proposes)

One-click presets + custom colors, auto default

The radio groups collapse into Reader-View-style presets (Dark, Light, Auto, Paper, Gray, High Contrast) with miniature scheme swatches, plus Background / Text / Accent color pickers with a contrast warning. Auto (follow OS) is the default — use the Theme select or the Accessibility panel to switch. Notices use the new neutral-text callout style. (The PR also persists prefs server-side for the settings UI; that part has no backend on this static preview, so here everything stays per-browser.)

What to compare

  • V1 → V3: overall readability of the light scheme vs the dark-only baseline.
  • V2 → V3: the accessibility menu itself — four radio groups vs one preset row + custom pickers.
  • Notices in the settings previews: V2 shows the earlier red-on-pink / blue-on-blue rendering; V3 the neutral-text version with the colored left border.
  • V3 custom colors: any Background / Text pair under a 4.5:1 contrast ratio triggers a warning.

Note

Static snapshots — no live backend, just HTML + CSS + localStorage-backed JS. All three versions share the same localStorage keys on this host, so a theme chosen in V2/V3 carries over between the previews here; "Reset to defaults" clears it. Feedback welcome on the PR thread.
